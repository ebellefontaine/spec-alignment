# Public Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the missing adapter layer, GitHub Action entrypoint, and CI/CD workflows to make spec-alignment publicly shareable as v0.1.0-beta.

**Architecture:** 
- Four adapter modules inject I/O (git diff, file reading, LLM calls, GitHub API) into the pure `runAction` seam
- One entrypoint (`index.ts`) parses GitHub Actions inputs, validates config, constructs adapters, orchestrates the run, and reports results
- Two workflows: test on PR, build+bundle+commit dist on push to main
- Version pinned to v0.1.0 across package.json, README, and action.yml

**Tech Stack:** 
- GitHub Actions runtime (actions/core, actions/exec, @actions/github)
- Vercel AI SDK (for multi-provider LLM support)
- Octokit (GitHub API client for Checks API + reviews)
- Zod (for config validation)

**Spec:** [Design Doc](../specs/2026-08-16-spec-alignment-action-design.md)

## Global Constraints

- Version: v0.1.0 (experimental, breaking changes possible)
- Node.js: 18+ (per existing package.json)
- TypeScript: strict mode, no implicit any
- Config inputs: validated with Zod before adapters are constructed
- Testing: all pure domain logic has unit tests; adapters are verified manually before release
- Git operations: use actions/exec to shell out to git (never octokit git APIs)

## Implementation Notes

### Adapter Dependency Injection
All four adapters are instantiated in `index.ts` and passed to `runAction()` for maximum testability. In production, they use real I/O; in tests, they can be replaced with fakes.

### Config Validation with Zod
All GitHub Actions inputs are validated against `InputSchema` in the entrypoint. Config errors fail immediately with exit code 1 before any adapters are constructed.

### Dist Bundling
`npm run build` (via `ncc`) compiles TS to JS and bundles all dependencies into `dist/index.js`. This must be committed so GitHub Actions can load and run it without `npm install`.

### Error Handling Strategy
- Setup errors (bad config): exit code 1, action fails
- Runtime errors (LLM failure, etc.): mapped to Check conclusion per `fail_closed_on_error`, action exits 0
- This separation ensures config problems are fast-fail while judgment errors respect the user's policy
